# Event contract v1 (P0-03)

Authority: spec §9.3, development plan §6.1–6.3, §7.5. Machine-readable form:
`schemas/events/envelope.v1.schema.json`, `schemas/events/catalog.v1.yaml` (source),
`schemas/events/registry.v1.json` and `schemas/events/types/*.v1.schema.json` (generated by
`python -m tools.gen_event_schemas`; CI checks drift).

## Envelope

One row of `events` (§6.3). `payload` holds non-sensitive JSON only; sensitive content travels as
`sensitive_payload_ciphertext` (base64, envelope-encrypted) with `sensitive_payload_key_ref`
(both present or both null). Timestamps are RFC 3339 UTC with millisecond precision and a `Z`
suffix (`server.domain.clock.isoformat_utc`). IDs: `event_id = evt-<32 hex>`, aggregate IDs carry
the prefix declared per aggregate in the catalog (`task-`, `apr-`, `sch-`, `run-`, `agent-`, …).

## Aggregates and streams

Every state aggregate is serialized by `(workspace_id, aggregate_type, aggregate_id,
aggregate_seq)`; `aggregate_seq` starts at 1 and increases by exactly 1 per Event. Appends are
serialized with a per-aggregate advisory lock or expected-sequence compare-and-swap (P1-02).
The catalog declares each aggregate's state vocabulary and the **authority** table lists the
decisions that must come from ledgers/constraints, never from projections (V-P0-13):
approval consumption, run uniqueness, task graph, assignments, permissions, verification
independence, idempotency.

## Idempotency

`idempotency_scope = "<aggregate_type>:<operation>"` (must match the Event's aggregate type) and
`idempotency_key` are unique per `(workspace_id, actor_account_id, idempotency_scope,
idempotency_key)`. A retry with the same scope/key and the same canonical body returns the
original Event; the same key with a different body is `IDEMPOTENCY_CONFLICT` (V-P1-02/03).

## Canonical JSON and content hash

- Canonical form: RFC 8785 (`server.events.canonical.canonical_json`).
- `hash_body` = the envelope metadata fields listed in `server.events.hashing.HASHED_METADATA_FIELDS`
  (event_id, schema_version, workspace_id, aggregate_type, aggregate_id, aggregate_seq,
  channel_id, task_id, type, actor_account_id, caused_by, correlation_id, idempotency_scope,
  idempotency_key, policy_version, occurred_at, sensitive_payload_key_ref) plus `payload`,
  `sensitive_payload_sha256` (SHA-256 of the raw ciphertext bytes, or null) and `previous_hash`.
- `content_hash = SHA-256(canonical_json(hash_body))`, hex lower-case.
- `previous_hash` = `content_hash` of the Event with `aggregate_seq - 1` in the same aggregate;
  null for `aggregate_seq = 1`. This forms a per-aggregate chain; daily anchors over all chains
  are recorded separately (P1-01/P1-06).
- `recorded_at` and `content_hash` are excluded from the hash input. Crypto-shredding destroys
  only the DEK referenced by `sensitive_payload_key_ref`; bytes and hashes stay valid (V-P1-20).

## Validation order and stable error codes

`SchemaRegistry.validate` runs envelope → type/payload → hash and raises `ContractError` with:

| Code | Meaning |
|---|---|
| `SCHEMA_INVALID` | envelope violates the JSON Schema (missing field, bad format, unknown field, ciphertext/key mismatch, previous_hash rule) |
| `UNKNOWN_EVENT_TYPE` | type not in the registry |
| `UNSUPPORTED_SCHEMA_VERSION` | schema_version not supported for the type |
| `AGGREGATE_TYPE_MISMATCH` | type belongs to another aggregate |
| `UNKNOWN_AGGREGATE_TYPE` | aggregate not in the catalog |
| `AGGREGATE_ID_INVALID` | aggregate ID prefix does not match the aggregate |
| `IDEMPOTENCY_SCOPE_INVALID` | scope prefix differs from the aggregate type |
| `PAYLOAD_INVALID` | payload violates the type's schema |
| `HASH_INPUT_INVALID` | payload not canonicalizable or ciphertext not base64 |
| `HASH_MISMATCH` | content_hash differs from the recomputed value |

## Versioning rules

- `schema_version` is per Event and per type. Changes are **additive only** (new optional fields,
  new types marked `extension` with the baseline rationale). Removing or retyping a field, or
  changing hash inputs, is a new major version (`envelope.v2`, `<TYPE>.v2`) and old versions stay
  readable forever.
- The catalog is the single source; generated files are committed and drift-checked.
- Fixtures under `tests/fixtures/events/` are generated by `tools/gen_event_fixtures.py` and cover
  task, approval, schedule, schedule_run, agent streams, a ciphertext envelope, and 19 invalid
  cases with their expected codes.
